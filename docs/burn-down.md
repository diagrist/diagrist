# Burn-down

Debt we accept on purpose. Each entry gives the reason and what removes it. An entry is deleted in the change that
settles it, and that change says so in its description. The entries are sorted by the package that holds the debt;
the crutches that keep the predecessor's bytes are numbered, since they go together in one clean-up.

## Language and kernel (`lang`, `core`)

| Debt | Clean-up |
|---|---|
| **Areas repaint colours, not meanings** (ADR 0033). The kernel finds what to repaint by the values of a style table's rules (`areaColors`) and by the kinds of shape a class is drawn on, so a look that paints an element in a colour of its own, such as the heads of UML cards in their `tone=`, shows the area only on what is left; a stripe on a diamond follows both left edges as a chevron. | A role for the paint an area replaces, which looks name, once a look needs more than colour values. |
| **Operators are fixed in `lang`.** `OPERATORS` in `packages/lang/src/scanner.ts` knows the UML diamond ends; BPMN gateways or ER crow's feet would need a change there. | `operators` in `KindSpec`, handed to the scanner by `readKind`, with `lang` keeping `=`, `=>`, `->` and `--`. It changes `read-kind.ts` and the tables, which the work on variants rewrites, so it follows once that has landed, or with the first plugin that needs its own. |
| **`Theme` and the description reach no host.** `compile` takes a `theme` and returns a `description` and `anchors`, but the CLI passes no theme and drops the other two, so the words in `describe/` of every UML kind reach no user yet. | `--theme <file>` and `description` in `build --json`, or drop what still has no host by the first release. |
| **`Infer` stops at recursion, and `readKind` casts.** Children of fragments are typed by hand in `plugins/plugin-uml/src/sequence/source.ts`, and `readKind` asserts its result type. | Carry the child tables in the type when a second recursive kind arrives. |
| **No list of arguments.** A statement cannot take a variable number of arguments, so C4 writes grid names with commas (`grid cols a,b,c`). | A variadic last argument in `lang`; then the predecessor's spaces read again. |
| **Value descriptions are English in every locale.** The `expected` text of a value type (`a text in double quotes like ...`) is not translated in German messages. | Phrase value descriptions through the catalogue (ADR 0004). |
| **No JSON schema of a kind's statements as data.** No command reads or writes statements as JSON, so a schema of the typed values (`Infer`) would have no user. | Derive it from the tables when such a command arrives (ADR 0004). |
| **Spec references are plugin-internal** (ADR 0017). `implementing` in `plugins/plugin-uml/src/spec` keeps its marks as extra properties of the tables, which `lang` passes along without knowing them; the grammar JSON has no field for them. | When a second plugin cites a standard (BPMN, ArchiMate): a typed field in `lang`, emitted by `grammarOf`, with the walker of `src/spec/coverage.ts`. |
| **Classes of markers count as unused.** The kernel writes a rule only when a shape uses its class, and a marker in `<defs>` is no shape, so marker rules (`uml-hollow`, the symbols of class diagrams) are marked `always` and written into every picture of their kind, and C4 marks the rules of its looks' markers `always` so that `look=paper`, which writes only used rules, draws open heads. | The kernel counts the classes of referenced markers. |
| **One marker size per style table.** The kernel's markers share `markerSize`; class diagrams set 18 for the diamond of 16 pixels and draw each symbol in pixels of that size, while use case diagrams draw the triangle 10 long where the predecessor drew 14. | A size per marker. |
| **Pictures of one file do not share their sizes** (ADR 0021). Cells are inherited, but the fixed grid measures column widths and row heights per picture, so a variant with a wider label widens its column and the pictures of one file do not overlay pixel for pixel. | An optional `Kind.measure?(models)` the kernel calls once with every model of a source, its result handed to each `layout`; C4 returns the largest widths and heights. |
| **`set` and `drop` reach the top level only** (ADR 0021). A class inside a package or a nested fragment is changed by restating its block. | Address nested lines when a kind needs it, by a path such as `set pkg.order ...`. |
| **Ligatures of JetBrains Mono.** Browsers join texts such as `->` in labels, while the layout measured single glyphs. Fixing it changes the bytes of every picture. | `font-variant-ligatures: none` on the root rule, with the second baseline of sequence diagrams. |
| **Two public types named `Finding`.** `core` calls the finding of a rule so, and `packages/cli/src/engine.ts` its diagnostic with a phrased message. | Rename the CLI's, such as `PhrasedDiagnostic`, once the variants work in `packages/cli` has landed; it changes the same files. |
| **Contextual alternates of Inter** (ADR 0022). resvg and browsers turn `->` and `=>` into an arrow glyph, narrower than the advances the table sums, and resvg has no switch for `calt`. Such texts take a little less room than measured, never more. | Read those substitutions from `GSUB` into the packed table, or switch `calt` off once resvg honours `font-feature-settings`. |

## Layout library (`layout-grid`)

Pieces stay in their plugin until a second kind needs them (ADR 0015); each comes into the library as data on the
spec and is compared number for number, as the path finding of state machines was.

| Debt | Clean-up |
|---|---|
| **Paths of one predecessor kind only.** The tile flow of C4 without a grid (fixed columns, bands, row gaps), the FigJam `elbow` profile and relations docking at attribute rows are not in the library. | Each comes back with its plugin. |
| **The layered layout of activity diagrams stays in the plugin.** Lanes, bars of fork and join, diamonds branching at their corners, loop channels, tracks for parallel jogs, pins and region names live in `src/activity/layout`; state machines, the second layered kind, brought their own rails, steps and loops. The engine has lanes as hard columns and hand-overs between them (ADR 0039, 11), but no bars over their branches (`shape: 'bar'`), no ends at fixed corners (`GraphNode.sides`), no loops in channels beside the lanes they pass, no room for pins and no handler bolts, so the kind cannot hand a layout graph without drawing its examples worse. | A stage for each of them, then activity hands a layout graph and `rank`, `columns`, `route`, `tracks` and `channels` go (layout plan P9). |
| **Labels along straight lines stay in the plugin.** Use case labels look along a slanted line, at both ends and inside the frame of the use case; notes search a field around their anchor. | Move the search for spots along a line into the library when a second kind draws straight lines. |
| **Options with one user so far, or none.** `onLine.avoid` and `detailFont` have no user yet: paper hands no rectangles and measures details in the label font, so its bytes stay; the panel and instrument looks drafted them. `rowMin`, `avoid` and `placeLabels` serve state machines, `demand` and `lines: 'straight'` use case diagrams, `cover`, `slot`, `bundle`, `lane`, `rowOverhang` and `indent` C4. All describe geometry a second kind can set unchanged: a least row height, rectangles a route keeps out of, labels a kind placed itself, the width a node asks of its columns, straight lines, a frame over one more column, equal places in an area, shared trunks, a column an edge runs in, room for what sticks out below a row, room left of the grid. `reserve` has two users, the names in the top edge of `look=columns` and the icon circles of cards (ADR 0023). `layering`, `LayeredFrame.tab`, edges with a frame at an end and loops serve class diagrams; `reorder` has no kind left that sets it, since class diagrams hand the graph of their layers instead, and goes with the layout graph of the plan's P7. The channel stage (`channels`, `GridGroup.head`, `signEdges` with its `pins`, `gutterRoom` with `widen` and `GridColumn.gap`, ADR 0038) and the adaptive grid's `drops` and `lead` serve C4 alone, and `signEdges` with `placed` C4 and the layered pipeline; use case diagrams could take it for their fixed grids. | They stay as options. |
| **Two contracts for the layered layout, and fields no stage reads yet.** `layoutGraph` takes the layout graph (ADR 0039), and `layoutLayered` with `LayeredSpec` stays as its adapter, which the stages still run on; state machines without points, regions and bars use it (P8), activity diagrams and the adaptive C4 grid do not yet. `GraphNode.sides` and the container `part` are in the contract, but the stages place ends on top, bottom and facing sides and lay regions out as frames; `lane` is a hard column (ADR 0039, 11). | The stages on the layout graph and `layoutLayered` gone, one release after P8 to P10 moved; `sides` and parts with the step that reads them (P8, P9). |
| **Disconnected parts of a scope are layered side by side.** `layerGraph` lays out each connected part on its own, where the predecessor ordered all vertices of a state's scope at once. All examples are connected. | An option to layer a graph as one part, if a machine needs it. |
| **Bends that only a move past a neighbour would spare stay.** Ports slide off the middle wherever both ends of a piece can reach one vertical; a bent piece is taken out by moving a box, a placeholder chain or a frame within the room of its layer when the whole picture drawn costs less by `scoreOf` and no link of a chain bends (layout plan R1, and R2 as a pass after the placement). A line whose boxes stand further apart than their room stays bent: `Kunde` in `pakete-drei` would need the frame `buchung` under `Rechnung`, and `buchung` in the layer of `abrechnung` runs `Rechnung -> Reservierung` through `buchung` (measured). A line that has to pass a frame lying wholly between its ends runs through it (`speichert` in `hexagonal`), which the order reaches by moving the placeholders of a whole chain to an end of their frame at once. Placeholders still pull eight times in the placement itself (R2 as a weight measured: four hard breaches more in the class stress set), and tracks do not count verticals side by side (R3's `apart` turns `raute` from 5 crossings to 13). `avoidable` of `lineMetrics` counts what is left in the stress budgets. | Moves that swap a box with its neighbour or a frame with another, priced by `scoreOf`, and R3 once the bus of `raute` exists. |
| **The order sees length only through an estimate, and trunks only where they meet their own box.** The order of shorter lines (ADR 0039, amendment of 06.11.2026) estimates where boxes stand by centring every layer, so it is drawn beside the order of fewest crossings and kept only where the drawing trades better; a picture with such an order lays out two rough drawings more (`dg-n-big` about 0.1 s, 230 to 233 crossings for 2,026 px less line). Of the crossings trunks make, the order counts those with pieces of their own box; two trunks of different boxes it counts piece by piece, which is why `schnittstellen` keeps its 5 crossings (the lattice of four interfaces needs about that many). In `beobachter` the trade leaves a bend a straight line could spare and two short jogs, where the placeholders between `Kursquelle` and `PreisBeobachter` share their room evenly instead of by the texts at each end. | Trunks as one piece in the order (a placeholder per trunk), the room beside a line split by the texts at its ends, and moves that take a box beside a chain along. |
| **Ports are placed by four placers, and one of them orders the ends of all sides** (layout plan P3, rule R3). The layered pipeline places the ends of pieces, of lines beside a layer below and above it, in one order per side, lets the ends of fans and joins give way to pieces that run straight, keeps ends below off the verticals of lines beside their layer, and bends each line beside its layer to the side where it crosses fewer pieces, counted on the ports of the placement, in hub pictures too. Lines with a frame at an end take the port of a box of the frame and are cut at its outline, so they share that order. The channel stage of C4 (`route/channel/ports.ts`), the adaptive grid (`route/adaptive-ports.ts`) and the rails and steps of state machines on the adaptive grid still place their own; rails of the pipeline order their ends per side (`rails.ts`), not yet in the one order with the pieces. | The adaptive grid on the pipeline (P10); the last state machines on the pipeline. |
| **Chains stand straight only outside hubs.** The links of a chain (`spinesOf`: two or more edges of one bundle in a row, each the only one of its bundle at both ends) are set straight after the other passes; a hub picture skips it, since its search for the sides of its extensions prices every arrangement by its routes, and straightened chains made it choose worse sides (`hub-fuenf`). | Straighten chains inside the search, so it prices them too. |
| **Frames make room for their head by widening where moving costs more.** A line entering a frame from above too near its head moves, with the node it enters and what stands beyond, right past the head (`clearOfHeads`), unless that leaves a head crossed or the picture costs more by `scoreOf` than the frame widened at the left and its empty strip, priced at twice its width. Outermost frames then close up to the left with their neighbours and what hangs below them where that is cheaper (`squeezed`), so `pakete-quer` is 1,232 px wide instead of 1,759. A frame whose own first box sits under its head still widens. | Ends of lines that enter a frame placed right of its head in the port stage, so neither a move nor a strip is needed. |
| **The line check reads lines from the anchors and finds their texts by key** (ADR 0035). `linesOfDrawing` in `core` takes a line per edge anchor, ties a text to the line whose index its key names (`<id><n>.label.<k>`, `label-<n>`), and reads lines that meet at one of their ends as a bundle. A kind that names its texts otherwise, or draws two lines from one point that are no bundle, is read wrongly. Sequence messages hand no `span` with their anchors, so a finding about one would stand at the first line; no example has one. | Lines as `Placed` with an outline and their own key (ADR 0020), handed by the kinds with their bundles and spans; then the key convention goes. |

## UML (`plugin-uml`)

### Sequence diagrams keep the predecessor's bytes (ADR 0008 Nr. 5)

The 15 examples render the predecessor's SVG byte for byte. These crutches keep it so; they go in one clean-up
with a second baseline.

1. **Base stylesheet always written.** 24 rules marked `always` in `packages/core/src/standard/styles.ts`, also
   in pictures that use none of them. Clean-up: drop `always`, the kernel writes only used rules.
2. **All four arrowheads in every `<defs>`** (`MARKERS`). Clean-up: write only referenced markers.
3. **Root class `dia`** (`standardStyles`). The target is `diagrist`, and `--dgr-` for CSS variables.
4. **Unrounded path numbers and circle radii** (`r="5.151515151515151"`), while rectangles, lines and texts are
   rounded to one decimal in `packages/core/src/svg.ts`. Clean-up: one rounding for all numbers.
5. **Arithmetic order of the layout.** `src/sequence/layout` keeps the predecessor's order of floating point steps
   (the right edge of a note is passed on, not recomputed as `x + w`). Refactors there must keep the bytes; the
   module TSDoc of `src/sequence/layout/index.ts` and of `packages/layout-grid/src/layout.ts` says so where the code is.
6. **Measuring by size, not by font role.** The layout measures with token sizes (`messageSize`) instead of the
   font roles of its style table. Clean-up: measure with `FONTS`.
7. **Card look in code.** `look=cards` changes shapes in `scene/cards.ts`, not only the style table.

Waiting for the same clean-up, because they change the bytes: `label-<i>` is never written, although the SVG
contract names it and `EdgeAnchor.labelId` exists (message labels need a group with the id); and heads, notes,
frames and labels are not handed to the placement check, which would report what the examples overlap.

| Debt | Clean-up |
|---|---|
| **Areas show weakly in `look=cards` and between lanes** (ADR 0033). Card heads keep their `tone=`, so sequence heads, lane heads and state cards show their area only in the outline or the stripe; neighbouring activity lanes share a border, which takes the tone of the lane drawn later; interruptible and expansion regions and sequence fragments take no `area=`. | Let a card head take the area's ink when it names no tone; draw shared lane borders once, in ink. |
| **U400 points at the statement, not the token.** `msg a -> b` reports column 1 instead of the `b`. | Carry the span of the offending end through the model. |
| **Completion knows no lifelines in `msg`.** Message ends are no `ref`, since they may also be `found`, `lost`, `gate` or a frame (`messageEnd` in `src/sequence/grammar/values.ts`), and the same holds for `over=`. | Let a value name the declarations it accepts besides its own forms, without `lang` checking them. |

## C4 (`plugin-architecture`)

### C4 crutches left from the predecessor's bytes (ADR 0016)

Every C4 picture took a second baseline when fixed grids moved onto the channel stage (ADR 0038); the inline paint of
the legend separator, `abgeloest`, the predecessor's arithmetic and paper's old test of a seated number went with it.
Icons went the same way: they are path data drawn by the kernel as a nested `<svg>` and painted by class in every
look, so `Icon.markup` and `RoleStyle.paint` are gone, and they are drawn at the size the look measures instead of
the predecessor's scale rounded to a tenth. One crutch remains.

**Blocks restate base rules** (`blockBase` in `src/looks/blocks.ts`): 13 base rules again with larger fonts and
strokes. Clean-up: the kernel builds the standard look from measures.

| Debt | Clean-up |

No example uses them. | Each with its tables, a predecessor example and its bytes. |
