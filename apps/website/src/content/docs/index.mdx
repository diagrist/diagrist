Diagrist turns small text files (`.dgr`) into diagrams. The language is strict on purpose: every statement,
argument and attribute is listed in a table, a check names what it found and what is allowed, and the same file
always gives the same SVG, byte for byte. So a diagram can be reviewed, diffed and fixed like code, by people
who keep diagrams next to their code in git and by coding agents.

## UML, C4 and code

The UML kinds are laid out by Diagrist itself. C4 diagrams place their elements in a named grid that the file
declares, so the author decides what stands next to what; a `flow` numbers the steps of a path, and an `adr`
explains a mark in a bar below the picture.

<Diagram source={bikeRental} name="bike-rental.dgr" />

A mistake looks like this:

```text
order.dgr:4:29  L105  error: `participant` has no attribute `stereotyp`. Allowed: `stereotype=`, `tone=`.
  participant pay ":Payments" stereotyp="external"
                              ^^^^^^^^^^^^^^^^^^^^
```
